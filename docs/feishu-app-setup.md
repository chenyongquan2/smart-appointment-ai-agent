# 飞书应用申请与配置操作指引

> 本文是 OpenSpec change `feishu-channel-integration` 的**前置条件操作手册**——列出接入飞书 Channel 需要你去开放平台取哪些材料、怎么取、怎么自检取对了。
> 拿齐材料后回到 [tasks.md](../openspec/changes/feishu-channel-integration/tasks.md) 的 §3 继续。
>
> ⚠ 飞书开放平台的界面文案和菜单位置会随版本调整。下面的按钮名称以**当前控制台实际显示为准**，若某处对不上，按「这一步要达成什么」去找对应入口即可。

## 你最终要交出的东西

| 材料 | 去哪取 | 填到哪 |
|---|---|---|
| `App ID` | 开发者后台 → 凭证与基础信息 | `.env` 的 `FEISHU_APP_ID` |
| `App Secret` | 同上 | `.env` 的 `FEISHU_APP_SECRET` |
| 一个测试群（机器人已入群） | 飞书客户端里建 | 手工验证用 |
| 一条真实事件的 JSON 载荷 | 见 [步骤 8](#步骤-8必做打一条真实事件看字段) | 决定会话键怎么定义 |

`App Secret` 等同密码：**只在 `.env` 里放，`.env` 不进 git**（仓库已 gitignore）。不要贴进聊天、issue、提交信息。

---

## 前置条件

- 你所在的飞书企业（`finpoints` 组织）允许创建自建应用。若创建入口是灰的，说明管理员限制了权限，需要找企业管理员开通「应用开发者」角色。
- 自建应用发布需要**企业管理员审核**。你自己是管理员就能自审通过；否则要找管理员点一下。这是最容易卡住的一步，建议提前问清楚谁能审。

## 步骤 1：创建企业自建应用

1. 打开 <https://open.feishu.cn/app>，用公司飞书账号登录
2. 「创建企业自建应用」→ 填名称（如 `预约助手-测试`）、描述、图标
3. 创建后进入应用详情页，地址栏里的 `cli_xxxxx` 就是 App ID

> 「企业自建应用」而不是「商店应用」——后者要走上架审核，我们不需要。

## 步骤 2：记下凭证

左侧「凭证与基础信息」：

- **App ID**：`cli_` 开头
- **App Secret**：点「查看」或「重置」获取

先原样存好，最后一起填 `.env`。

## 步骤 3：开启「机器人」能力 ⚠ 最容易漏

左侧「应用能力」→「添加应用能力」→ 启用 **机器人**。

**没有这一步，后面的事件订阅和发消息全都不可用**，而且报错信息未必直说是缺能力。启用后可以顺便设置机器人的名称与头像（群里显示的就是它）。

## 步骤 4：申请权限

左侧「权限管理」。权限列表很长，**别翻中文列表——直接把下面的机读名粘进搜索框**。

**必需（本期只用到这两条）**

| 机读名（搜这个） | 中文描述 | 用途 |
|---|---|---|
| `im:message.group_at_msg:readonly` | 接收群聊中@机器人消息事件 | 本次接入的触发源 |
| `im:message:send_as_bot` | 以应用的身份发送消息 | 发 ack 与结果回复 |

**建议一并开（省得以后再走一遍发版审核）**

| 机读名 | 中文描述 | 何时用到 |
|---|---|---|
| `im:message.p2p_msg:readonly` | 接收用户发给机器人的单聊消息 | 将来支持私聊 |
| `im:chat:readonly` | 获取群组信息 | 排障时看群名 |
| `contact:user.base:readonly` | 获取用户基本信息 | 把 `open_id` 显示成人名 |

> ⚠ 别勾 `im:message`——它是大包权限，虽然含了发消息能力，但授权面大得多。用上面两条精确的即可（最小权限原则；本项目的 oncall 域将来要求全工具只读，这个习惯要一开始就立住）。
>
> 若控制台提供「批量导入权限」（粘贴 scope 列表）入口，直接贴机读名最省事。

## 步骤 5：事件订阅选「长连接」

左侧「事件与回调」→「事件配置」：

1. **订阅方式选「使用长连接接收事件」**（不是「将事件发送至开发者服务器」）
2. 添加事件：**接收消息 `im.message.receive_v1`**

选长连接的原因：本地开发机没有公网地址，回调模式需要飞书能主动访问你的服务器。长连接是我们的服务主动连出去，内网也能跑（设计决策见 [design.md](../openspec/changes/feishu-channel-integration/design.md) D1）。

## 步骤 6：创建版本并发布

左侧「版本管理与发布」→「创建版本」→ 填版本号和更新说明 →「申请发布」。

**关键认知：权限和事件订阅的改动，必须发布新版本才生效。** 后面若再加权限，要重走一次这个流程。

可用范围建议先设成「仅指定成员」并只勾你自己 —— 测试期间不打扰同事，将来再放开。

等管理员审核通过（自审的话点一下就行）。

## 步骤 7：建测试群并拉机器人进群

1. 飞书客户端里新建一个群（如 `预约助手测试`），成员先只有你
2. 群设置 →「群机器人」→「添加机器人」→ 搜到刚发布的应用 → 添加
3. 在群里发一条 `@预约助手-测试 你好` 试试

此时机器人不会回你——服务端还没写完，这是预期的。能 @ 出来、消息发出去，就说明前六步都对了。

## 步骤 8（必做）：打一条真实事件看字段

**这一步的结论直接决定数据库表怎么建，所以必须在写 `channel_session` 表之前做。**

背景：设计里用「会话键」把飞书的一次对话映射成 Agent 的 `session_id`。但 `thread_id` 只在**开启了话题模式的群**里才下发，普通群 @ 机器人的消息大概率只有 `chat_id` / `message_id` / `root_id`。这是我基于飞书 API 的判断，**不是实测结论**——必须用真实载荷验证。表一旦写入数据再改键定义，就要做迁移。

拿到凭证后告诉我，我会写一个一次性的探针脚本：连上长连接、把收到的第一条事件整个 JSON 打到终端，不入库、不回复。你在群里 @ 一下，我们一起看这几个字段到底有没有值：

- `thread_id`（可能没有）
- `root_id` / `parent_id`（回复链）
- `message_id`、`chat_id`、`chat_type`
- `sender.sender_id.open_id`（用来把长期偏好按人隔离）

看完再决定会话键的优先级链，然后才动 tasks 3.3 的建表。

## 填入 `.env`

```env
FEISHU_ENABLED=true
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
FEISHU_DOMAIN=https://open.feishu.cn
FEISHU_SESSION_SCOPE=thread
```

- `FEISHU_DOMAIN`：国内飞书用 `open.feishu.cn`；国际版 Lark 是 `open.larksuite.com`（两者 API 同构，代码一份跑两实例）
- `FEISHU_SESSION_SCOPE`：`thread`（默认，一次 @ 开一条会话）或 `chat`（整群共用一条会话）
- 这些键名会在 tasks 3.1 一并写进 `.env.example`

## 运行约束 ⚠

启动服务时**必须单 worker**：

```bash
uv run uvicorn app:app --host 127.0.0.1 --port 8001 --workers 1
```

多 worker 会起多份长连接、同一条消息被消费多次，而事件去重表是进程内的，**拦不住跨进程重复**。重复消费意味着重复下单（`create_appointment` 目前没有幂等键）。

开发时用 `--reload` 会在每次热重启时断开重连，建议把 `FEISHU_ENABLED` 改成 `false`。

## 自检清单

拿齐后逐条确认，全打勾再进 §3：

- [ ] App ID / App Secret 已记录，且 `.env` 没有被 git 跟踪
- [ ] 「机器人」能力已启用
- [ ] 三条必需权限已勾选
- [ ] 事件订阅方式是**长连接**，已添加 `im.message.receive_v1`
- [ ] 已创建版本并**审核通过**（状态显示「已发布」）
- [ ] 测试群已建，机器人在群成员列表里
- [ ] 群里 @ 机器人能正常发出消息

## 常见坑

| 现象 | 原因 |
|---|---|
| 事件订阅里找不到「长连接」选项 | 「机器人」能力没启用（步骤 3） |
| 权限勾了但调 API 报无权限 | 改完权限没有重新发布版本（步骤 6） |
| 群里搜不到机器人 | 版本没审核通过，或可用范围没包含你 |
| 报错 `230027` | 用 bot 身份读话题历史会被拒，该场景需要 user 身份（本期用不到，第 3 期读历史时才会遇到） |
| 长连接连上但收不到事件 | 事件里没加 `im.message.receive_v1`，或消息没有真的 @ 到机器人 |
