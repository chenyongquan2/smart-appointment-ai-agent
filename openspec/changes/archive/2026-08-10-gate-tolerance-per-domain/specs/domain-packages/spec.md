## MODIFIED Requirements

### Requirement: 领域包的结构与内容

系统 SHALL 把「领域」收敛为一个**可装载的包**，每个领域包 SHALL 提供且仅提供以下五样域绑定的东西：

1. **工具集**——该域可供模型调用的 `Tool` 定义；
2. **子 Agent 集**——该域的 `SubAgent` 定义（各自持有工具子集）；
3. **系统提示**——该域的人设、职责边界与红线文本；
4. **权限策略**——该域的危险操作判定策略；
5. **评估数据与标注口径**——该域的用例集与基线所在目录（`evals_dir`），**以及**一份 `EvalProfile` 声明，含该域的数据集标签集合、槽位键映射、门禁指标集、门禁容差四项。

第 5 项之所以不止是一个目录：评估机制要读用例，就必须知道「本域的标签叫什么、哪些工具入参算槽位、本域实际能守哪些指标、多大的抖动才算回归」。这四件事**换个域就不成立**，按判据它们属域绑定内容；把它们留在 `evals/` 会让「机制域无关」名不副实——装上另一个域的数据要么直接加载失败，要么门禁静默退化成守更少的项、或用一个按别的域校准的阈值守得过松。

领域包 MUST NOT 包含域无关的运行时机制（TAO 循环、`ToolRegistry` / `SubAgentRegistry` 结构、记忆分层、护栏、Tracer、系统提示的拼接逻辑、评估运行器、指标算法、门禁比对算法）。判据是一句话：**这段代码换成另一个域还成立吗？** 成立即属域无关运行时，MUST 留在 `harness/` 或 `evals/`。

`EvalProfile` SHALL 是**纯声明**（不可变数据，无行为方法），与 `Domain` 同属声明层；指标如何计算、门禁如何比对仍 MUST 留在 `evals/`。

#### Scenario: 领域包提供齐五样东西

- **WHEN** 装载任一领域包
- **THEN** 得到的领域对象含工具集、子 Agent 集、系统提示、权限策略、评估数据目录与 `EvalProfile`（四项声明齐全）五项，缺一即为装载失败

#### Scenario: 域无关机制不随域走

- **WHEN** 检查 `harness/` 与 `evals/`
- **THEN** 其中不存在任何具体领域的工具定义、子 Agent 定义、人设文本、标签名、槽位名、门禁指标组合或按域校准的容差阈值；`ToolRegistry`、`SubAgentRegistry`、系统提示拼接函数、评估运行器、指标算法均保持域无关

#### Scenario: EvalProfile 为纯声明

- **WHEN** 检视 `EvalProfile` 的定义
- **THEN** 它只承载不可变数据（标签集合、槽位键映射、门禁指标集、门禁容差），不含任何指标计算或门禁比对逻辑
